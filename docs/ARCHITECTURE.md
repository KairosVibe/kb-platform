# 架构说明

> R3 定位与交付：通用知识管理与 AI 问答平台，用于真实工程落地及简历展示；不转为电商/售后专用产品。继承 R2 功能编号和安全契约。当前只修订文档，尚未确认进入开发。详见 [交付、评测与文档确认](DELIVERY-EVALUATION.md)。

版本：2026-09-16 R3。本文为当前设计；不表示已实现或已完成生产验收。

## 1. 依据与边界

- 产品与函数规格分别见 [PRD](PRD.md)、[FUNCTION-MAP](FUNCTION-MAP.md)；已确认安全原则见 [DESIGN_REVISION](DESIGN_REVISION.md)。用户原始需求优先。
- 采用分层单体：Vue 控制台、FastAPI、MySQL、Milvus、外部模型适配。首版单实例受控发布，不采用蓝绿双活或微服务。
- 现有 core/权限代码只代表部分实现，旧创建者、超管、祖先部门授权分支及相关测试须按新契约修改。未重新运行测试，不沿用历史通过数证明当前正确性。

## 2. 模块职责与依赖

1. API：DTO、当前身份、功能权限、错误映射；不直接编排跨存储事务。
2. 身份与组织：用户状态、直属部门、角色、持久会话撤销；功能权限不产生知识正文旁路。
3. 知识服务：上传、版本、切片、ACL、启停删除、持久索引任务。
4. 授权引擎：权威状态读取与四维判定；纯 judge 只计算，authorize_units 负责读库；二者不能混称同一个纯函数。
5. 检索服务：向量与关键词候选、MySQL 状态版本复核、授权、有权候选融合及重排。
6. 问答服务：持久请求、FAQ 快路径、历史上下文、生成、事件、取消、引用。
7. FAQ/缺口服务：持久日志消费、聚类、来源关联、审核发布、失效、补充任务及原身份回放。
8. 审计指标：唯一请求事实、来源及调用用量、可重算聚合；不能只在成功回答结束时记录。
9. Provider：embedding、rerank、生成、向量存储；隔离版本差异，真实后端集成验收。
10. 后台执行器：从 MySQL 领取任务，租约与条件提交；进程内队列仅唤醒，不是唯一任务事实。

依赖方向：页面→API→业务服务→授权/检索/Provider/仓储。问答编排直接调用生成 Provider；检索调用 embedding/rerank Provider。文件存储持久保存原文，MySQL 保存位置与版本。向量库、倒排和 FAQ 缓存可重建，不决定最终授权。

## 3. 安全契约

1. 登录且启用，入口满足功能码；正文访问为 global OR 直属部门命中 OR 角色交集 OR 个人命中。全空拒绝；创建者和系统管理员没有自动读权；部门树不隐式继承知识授权。
2. kb:view 是管理台账最小元数据能力，正文另需数据读权；kb:perm 可显式配置授权并记录 before/after。普通问答受限提示不含 ID、标题、ACL 名称或数量。
3. 部分无权：剔除受限资料，根据有权证据回答并追加固定提示。全部无权：固定拒绝，不调用生成模型猜测。鉴权异常：失败终态，不降级放行。
4. 多来源 FAQ/历史答案必须每个来源当前可读且有效；来源之间 AND，每个来源内部四维 OR。不能合并成扩大读者范围的独立 FAQ ACL。
5. ACL、账号状态、角色变更提交后，新请求、历史、引用和输出批次复核。单实例内短临界区串联变更生效与发送决定，不能跨网络等待；已经发送的字节不可撤回。
6. refresh 会话及撤销持久化；注销不因重启失效。令牌用途、到期、会话状态均校验；令牌不携带长期有效权限快照。**"会话状态均校验"要求令牌自身携带会话标识**（实现为 payload 的 `sid`，见 FUNCTION-MAP H01）；否则 access token 在注销后仍有效至其自然到期（默认 2 小时），"注销立即生效"无法成立。`sid` 是标识不是快照，不含角色/部门/权限码。

## 4. 三条主链路

### 4.1 导入

校验与临时文件→MySQL 同事务登记单元/版本/任务→租约领取→解析清洗→持久切片→批量 embedding→版本向量 upsert→核验完整性→条件激活。

- 主键按 unit/version/seq 稳定生成；重复执行复用同版本切片。
- 激活必须匹配当前 content_version、有效 lease_token 和未删除状态；旧任务 superseded。
- 检索复核 enabled、未删除、indexed 状态及 content_version=indexed_version=切片版本。Milvus 标量仅预筛。
- 替换期间 stale，不返回旧内容；删除先墓碑和清理任务，再物理清理；旧任务不能复活单元。
- 临时失败退避，耗尽或永久错误 failed；租约过期恢复，不仅扫描单元 stale 就宣称幂等。

### 4.2 问答

接受唯一请求并建审计→当前身份→授权 FAQ 匹配→未命中则两路候选→MySQL 状态版本→四维授权→有权融合重排→授权历史与证据 Prompt→生成→先持久事件后发送→统一终态。

- 初始两路各 20，最多各 100，最终有权 Top5；均为待校准初值。
- 无权、无证据、低置信、索引不可用、服务失败分开；无权、索引不可用和服务失败不进入知识缺口。
- 请求唯一键 user_id/client_request_id；重连 GET 事件，不重新 POST 生成。事件 seq 单调，恢复先重新授权；保留期外取安全快照。
- done/error 在终态提交后发送；FAQ、拒答、失败、取消同样审计。用量未知为 null/unknown，不伪造零。

### 4.3 沉淀

领取未消费终态日志→语义分组→有效来源起草→候选和消费完成同事务→审核→发布内容缓存→每次命中当前来源授权。

- 唯一消费键 log_id/pipeline_version；不能只用最大自增 ID，避免漏掉晚提交记录。
- 模型调用在短事务外，稳定 job_key 复用起草结果；簇成员与代表相似度校验，不能只靠相似链传递。
- 来源变化使 FAQ stale 或强制复核；编辑已发布内容先下线重审。reject、offline、stale 分开。
- 正常无证据/低置信问题→部门+指纹缺口→独立补充任务→绑定文档→原合法身份回放命中新补版本→closed；不直接连接 FAQ 缓存。

## 5. 状态与数据约束

- 知识：pending/indexed/stale；启停、删除为独立字段。
- 索引任务：queued/running/retry_wait/succeeded/failed/superseded；阶段 parsing/embedding/indexing 独立。
- 问答请求：accepted/running/completed/rejected/failed/cancelled；业务 result_type 独立。
- FAQ：candidate/published/rejected/offline/stale；cache_enabled 独立。
- 缺口：open/processing/closed；processing 不能写入知识索引状态。
- 实体及唯一键见 FUNCTION-MAP §2.1，不锁死 17 表或 46 端点。完整 DDL/OpenAPI 仍需实现前生成并验证。

## 6. 编排与部署取舍

确定性业务编排采用普通 async 服务即可；授权是所有出口必须调用的契约，不依赖是否采用图框架。若未来需要动态工具选择、循环规划再评估编排框架，不据此放宽授权。

首版一个 API 实例含任务执行器和内存缓存。单进程不消除协程竞争，租约、唯一键、版本条件仍必须实现。Milvus Lite 与 standalone 为两种运行配置，需要分别验收；部署和迁移见 [DEPLOYMENT](DEPLOYMENT.md)。
