# ADR-0004：保留原项目改造选项，先验证运行基线

日期：2026-09-16。状态：提议，文档路线更新；未授权业务代码实施。

## Context

用户目标是通用知识平台实际落地与简历展示，要求继续评估原项目复用。当前文档过早限定少量移植，可能导致重复开发；源码又有身份、Mock降级、检索错误和SSE恢复方面的不兼容行为。

## Decision

保留两条路线：A沿原工程隔离改造，B新骨架迁入经验证组件。先按REUSE-MATRIX B0—B3验证A的启动、完整链路和可切割性，再选择。当前原目录保持不变，R3目标架构和安全标准保持。

## Alternatives

直接全部复制无法满足授权和持久化；直接全部重写浪费已有解析、模型和UI工作；仅因图框架或目录不同否决原工程也缺证据。采用有条件的渐进改造评估。

## Consequences

增加一次受控基线核验，但可避免低估迁移或重复实现。源码静态存在与运行通过分开记录，无法承诺固定复用比例或工期。

## Migration

记录来源哈希与许可→隔离运行基线→新身份和授权→持久化/任务→请求与SSE协议→运营闭环。确定唯一前后端入口与唯一权限/数据库事实源。原LangGraph仅可过渡，最终保留须更新决策与架构，不把当前async目标自动改回图编排。

## Compatibility / Rollback

旧接口、事件名及文档ID不承诺自动兼容新客户端；显式映射或受控切换。阶段回滚可以回到前一安全检查点，不能恢复客户端自报角色和默认放行。模拟索引可重建，不能混用不同embedding空间。

## Validation

本轮只核对文件、关键逻辑、文档链接和需求映射。业务测试、构建、原项目启动、云模型和真实数据库均未执行。B1—B4验证计划不是验证结果。
