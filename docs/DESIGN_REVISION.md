> R3 定位与交付：通用知识管理与 AI 问答平台，用于真实工程落地及简历展示；不转为电商/售后专用产品。继承 R2 功能编号和安全契约。当前只修订文档，尚未确认进入开发。详见 [交付、评测与文档确认](DELIVERY-EVALUATION.md)。

## 1. Goal、Non-Goal 与兼容性

Goal：交付可运行控制台、业务与检索服务、模型适配层、测试数据及覆盖问答和沉淀的端到端演示。覆盖组织管理、知识维护、四维权限、流式问答、FAQ、缺口、看板。

Non-Goal：首版不引入微服务、图谱、互联网检索、复杂 Agent 编排。生产容量、可用性承诺须经实际验收后确定。

保持现有 Vue/FastAPI/MySQL/Milvus 方向；单进程是首版部署约束，不是并发安全保证。真实服务用于集成验收，单元测试允许 stub。不以未经验证的供应商版本兼容说明作为实现事实。

2026-09-16 状态校正：已有部分 core 与权限实现；旧权限分支与测试仍需对齐。本文不证明数据库迁移已实现；实施前盘点实际数据并补迁移设计。

## 2. 权限契约

### 2.1 数据读取

用户必须登录且启用，入口还须满足对应功能权限。知识正文读取统一判定：

`unit.global OR user.dept_id ∈ unit.department_ids OR user.role_ids ∩ unit.role_ids ≠ ∅ OR user.id ∈ unit.user_ids`

（字段名取自 FUNCTION-MAP §1 `UnitState`。接口层 `PUT /api/knowledge-units/{id}/acl` 的 `depts/roles/users` 与之一一对应，是同一四维配置的两种记法。）

规则：默认全空拒绝；部门仅直属部门匹配，不隐式继承祖先或子孙；创建者和系统管理员没有自动正文读权。管理员需要阅读时显式配置角色或个人授权。停用、删除的知识不可被问答使用；用于问答的切片还必须匹配当前可检索版本。

知识维护功能授权与正文读权分开：具有 kb:view 可查看管理台账，编辑正文/查看切片须同时具备相关操作权限与数据读权；上传返回任务状态，不自动配置创建者读权。kb:perm 是敏感授权能力，可修改知识 ACL，必须记录 before/after；能够授予自身读权是该能力的显式管理权力，不是隐蔽旁路。

系统管理员默认管理组织、功能授权、配置和看板；知识管理操作须分配对应权限码。14 个权限码保留：ai:ask、kb:view、kb:upload、kb:edit、kb:delete、kb:perm、faq:review、faq:publish、gap:handle、dashboard:view、sys:user、sys:role、sys:dept、sys:model。菜单和按钮不代替后端检查。

### 2.2 鉴权结果

内部返回 allowed_unit_ids、denied_unit_ids、unavailable_unit_ids；鉴权异常为独立错误，不伪装成无权或零召回。

| 情况 | 行为 |
|---|---|
| 全部有权 | 使用有权证据生成 |
| 部分无权 | 仅使用有权证据；追加“部分参考资料因权限受限无法展示” |
| 全部无权 | 固定受限提示，不调用生成模型猜测答案 |
| 正常检索但无足够相关证据 | 返回无可用知识说明，可进入缺口判定 |
| 鉴权/检索服务异常 | 错误终态，不降级放行、不产生知识缺口 |

客户端 denied 只含 reason_code=ACCESS_RESTRICTED 与固定 message，不含受限 ID、标题、摘要、部门名单、正文或数量。完整受限列表仅保留在受控审计中。

### 2.3 即时生效与历史

以权限变更事务提交为生效点。新请求、FAQ 输出、引用打开、历史读取和下一轮上下文构造均复核当前权限与来源状态。缓存不是授权事实来源。

历史答案记录来源 unit_id/version；任一来源不可读时，整段派生答案隐藏并显示受限占位，禁止回填模型上下文。未记录来源的知识型历史答案不作为上下文。会话始终校验所有权。

单进程内，ACL/用户状态/角色成员变更与输出批次共享短临界区：提交失效事件并取消受影响流；每个发送批次检查最新状态，失败终止。多实例部署前须替换为跨实例一致的机制。已经发送到客户端的内容无法撤回；即时生效不作追溯抹除承诺。

## 3. 检索与问答

认证 → FAQ 候选匹配和来源授权 → 未命中则向量/关键词召回 → MySQL 状态及版本复核 → 四维授权 → 有权候选融合/重排 → 有权证据构造 Prompt → 流式输出。

初始两路各 Top20，可配置地扩大候选窗口至 100；最终选有权 Top5。窗口用尽仍不足时按实际证据回答，不声称全库不存在。受限候选仅用于固定提示和受控审计，不发送至回答阶段的外部重排服务。所有知识的 embedding 外发仍须遵守企业认可的数据出域政策。

分数分别保存 dense_score、lexical_score、rrf_score、rerank_score 和模型版本。缺口阈值不能直接套用 RRF 分数；初值仅为待评估参数，用带相关性标签的数据集校准。

智能联想、引用详情、来源定位与历史回答使用同一数据权限规则。Markdown 禁止不受控 HTML；链接协议白名单，代码块按文本渲染。

## 4. 索引版本与持久任务

knowledge_unit：content_version、indexed_version、index_status(pending/indexed/stale)、enabled、is_deleted、acl_version。

parse_task：unit_id、target_version、stage、status(queued/running/retry_wait/succeeded/failed/superseded)、attempts、next_retry_at、lease_until、lease_token、error_code。

1. 上传/替换/切片修改在 MySQL 同一事务增加内容版本、写入版本内容与唯一任务；单元进入 pending 或 stale。权限修改只增加 acl_version，不重做 embedding。
2. 任务以条件更新领取并持有租约；stage 表示 parsing/embedding/indexing。续租或提交必须匹配 lease_token。
3. 向量主键稳定取 unit_id:version:chunk_seq；同一版本切片结果持久化后重试复用，避免重试产生不同切片集合。
4. 写入并校验全部目标向量后，条件提交：当前版本仍等于 target_version、未删除且租约匹配，才更新 indexed_version 和 indexed 状态；旧任务标 superseded。
5. 查询最终放行条件为 enabled、未删除、index_status=indexed 且切片版本等于 content_version/indexed_version。Milvus 标量过滤只作预筛，不能替代 MySQL 复核。
6. 删除事务先设置 tombstone 并登记清理任务；失效 FAQ 与活动流。物理清理可重试；过期任务无法重新激活已删除单元。清理任务保留至确认完成。
7. 临时网络错误退避重试，建议最多 5 次；空文本、加密、不支持格式等永久错误不自动无限重试。租约过期恢复执行；达到上限转人工重试。

首次实现选择更新期间不可检索，以牺牲短暂可用性换取不返回旧内容。MySQL 与外部索引之间不存在原子事务，不作此承诺。

## 5. FAQ、挖掘与缺口

FAQ 状态：candidate/published/rejected/offline/stale。保存答案版本、来源 unit_id/content_version 列表、审核人、发布时间、缓存开关。

多来源 FAQ 必须满足每一个来源的当前数据读权，即来源之间 AND，每个来源内部四维 OR；禁止将所有来源 ACL 合并为一个宽松 OR。来源为空不得自动发布；来源正文变更或删除转 stale 并清缓存，重新审核后发布；权限变化重新鉴权，绝不只依赖发布时的 ACL 快照。编辑已发布答案先下线重新审核。

FAQ 管理列表和参考答案须校验审核人的来源读权。缓存键与条目携带 FAQ 版本、来源版本；服务端复核已发布及全部来源状态。缓存只缓存内容，不缓存永久放行决定。

精确规范化问题命中可避免模型调用；语义命中需要查询 embedding 时，记录真实调用与耗时。毫秒级是缓存服务阶段目标，不宣称包含远程模型的整链路恒定小于 100ms。

日志挖掘按持久消费状态读取已完成问答，唯一键 qa_log_id+pipeline_version 防重复；不能仅用自增 ID 最大值跳过晚提交记录。LLM 调用在数据库事务外执行，以稳定 job_key 保存结果；归簇登记与消费完成同事务提交。调度器 max_instances 仅防本地重入。

相似问题不能仅凭连接关系无限传递合并；设置簇代表问题相似度约束，并记录来源和权限边界。候选答案应依据有效来源生成，不把历史模型回答直接当事实。

结果分类：answered/faq_hit/access_restricted/no_evidence/low_confidence/service_error。仅正常检索的 no_evidence/low_confidence 入缺口；权限不足、索引尚未就绪和服务错误不入缺口。混合结果存在相关无权资料且无足够有权证据时，归 access_restricted。

缺口按规范化问题指纹及部门聚合，转建操作带幂等键，open → processing → closed。闭环需在原问题权限上下文下回放命中新补资料；仅上传完成不自动关闭。知识管理员仅查看其可管理范围的提问与日志，禁止通过聚类页暴露受限答案。

## 6. 流式协议与审计

POST /api/chat/requests：session_id、client_request_id、question。唯一约束(user_id,client_request_id)，同键同载荷复用请求；异载荷 409。会话归属检查后才创建记录。

GET /api/chat/requests/{id}/events?after_seq=N：只附着已有请求，不重新生成；每个事件含 request_id、seq。事件先持久化后发送。恢复时重新鉴权；权限已撤销不重放原文，返回受限终态。事件保留期作为部署配置明确。

POST /api/chat/requests/{id}/cancel；GET /api/chat/requests/{id} 返回已授权的状态及快照。暂定路径是新协议设计，不宣称已有端点。

请求状态：accepted/running/completed/rejected/failed/cancelled。进程崩溃由恢复扫描把遗留运行请求终结为 failed，不自动再次付费生成。网络断开可继续持久执行，用户取消才停止；受并发上限和超时约束。

事件：meta、delta、citations、denied、heartbeat、done、error。心跳不要求持久化，数据事件单调序号；终态记录提交后才发送 done/error。使用 fetch 流读取。

审计在请求接受时创建，再更新终态；记录用户、会话、问题、来源版本、召回/放行/拦截列表、结果类型、耗时及用量。token_usage_status=known/unknown/not_applicable：FAQ 无生成调用的生成 Token=0；异常缺失用量为 unknown，不能伪造 0。embedding/rerank/生成调用分开计量。

## 7. 数据与接口边界

不预先锁死“17 表/46 端点”。实体至少覆盖组织、知识与版本切片、持久任务、会话请求与事件、FAQ 来源关系、日志消费、缺口和审计；具体 DDL 与完整 OpenAPI 是下一实施门槛。

必须唯一约束：user 登录标识、user_role(user_id,role_id)、parse_task(unit_id,target_version)、chunk(unit_id,version,seq)、chat_request(user_id,client_request_id)、chat_event(request_id,seq)、faq_source(faq_id,unit_id)、mining_consumption(qa_log_id,pipeline_version)。高频扫描索引覆盖任务状态/next_retry_at、问答时间、缺口状态/last_seen_at。

API 组：认证与当前用户；部门/用户/角色；知识台账/内容/ACL/上传批次/解析任务；会话与问答请求；FAQ 候选/发布/下线；缺口/转建；看板与配置。每个端点在 OpenAPI 中注明功能权限、对象归属、数据授权、幂等、分页、错误码。

角色与部门删除遇到引用默认 409，要求先迁移成员或撤销引用；部门不能移动到自身后代。ACL 提交校验所有实体存在。配置接口密钥写入后不回传明文、不写日志；模型配置版本与调用审计关联。

## 8. 导入与运营口径

文件夹由前端展开成文件清单，保留相对路径作展示元数据，禁止将客户端路径用作磁盘路径。批次逐文件显示上传与解析状态，部分失败可单独重试；sha256 只在适当权限范围内去重，避免跨权限泄露文件存在性。20MB/文件沿用暂定值，批量数量、总大小、并发与解析时限须配置。

Word 的 DOC 支持与扫描 PDF/OCR 属范围待确认项：当前仅保证 DOCX 与有文本层 PDF 的旧设计不能称为完整格式验收。实现前确定支持或业务接受的排除项；不得静默忽略导入失败。

PV=成功接受的唯一问答请求数，包含 FAQ/拒答/后续失败，不含认证失败和幂等重连；UV=同期这些请求的去重用户。FAQ 命中率=成功 FAQ 直出/PV。知识覆盖率=(有足够授权证据的 RAG 回答+有效 FAQ 回答)/PV，另外展示纯检索召回率和错误率，避免混淆。

知识总数=未删除单元数，另分启用/已索引；知识热度=每轮对有权引用单元去重计数。延迟记录首字和终态两项，按成功/失败分布展示；用量未知单独计数。时间按 Asia/Shanghai 自然日和 ISO 周。

## 10. 实施门槛、风险与回滚

实施顺序：身份与权限真值测试 → 知识版本和任务故障测试 → 非流式授权问答 → 流式恢复与历史 → FAQ/缺口 → 看板与演示。测试跟随每阶段，不留到收尾补齐。

至少一个完整客服沉淀/补档演示，并用自动化和简短财务隔离回放覆盖四维权限。原 31–40 人日为修正算术后的历史估算，不是新增细化后的承诺；完整接口/DDL、格式范围与容量目标确定后重估。

上线门槛：上述用例、真实模型和向量后端集成验证、备份恢复演练、容量与并发测试。待定容量需列出文档/切片数、并发问答、导入规模、首字/P95、恢复时间，不虚构实测值。

回滚：设计文件先备份；实现前无需数据回滚。未来索引回滚不得重新放行过期内容；模型/切片版本切换须重建并验证后启用。参考项目保持只读。
