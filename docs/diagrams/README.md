## 语义说明与省略范围

1. 图01是模块依赖概览，不是独立服务部署拓扑。API、业务、权限、适配、执行器和内存缓存共一个进程；反向代理/TLS和持久卷详见DEPLOYMENT。后台执行器从MySQL领取租约，经模型适配向量化；这些次要连线以说明补充，不能理解为没有依赖。
2. 图02的“重试或失败”涵盖解析、embedding和向量写异常；瞬时失败返回领取，永久或耗尽终止。删除/替换立即使旧内容不可检索，后续清理或新版本重走登记链路。无法在格式校验阶段发现的解析错误在任务阶段报告。
3. 图03只画可回答主链路及FAQ快路径；图07画完整结果分流。无证据、全部受限、低置信和服务故障不得混为一类。未标文字的箭头表示顺序调用，节点已说明动作，无额外隐含协议。
4. 图04是两条独立闭环。缺口来自问答终态的持久任务，不是由FAQ驳回生成；补档不会直接写FAQ缓存。回放失败保持processing；FAQ重新提交审核按API中的resubmit契约。
5. 图05主路径展示事件持久化、读取、授权及发送；终态节点包含最终事件持久化，与审计同事务。正常终态事件同样经读取/安全发送，省略重复回边；撤权连接只发送安全错误，不泄露旧事件。
6. 图06保留文档确认门禁；评测或恢复不通过必须返回对应阶段修正，不擅自降低门槛或进入正式交付。
7. 图07的“登记知识缺口”逻辑上包含与终态同事务的outbox登记，实际聚合异步执行。UI不等待聚类或缺口消费者完成。
