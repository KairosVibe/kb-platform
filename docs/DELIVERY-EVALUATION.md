# 通用知识管理与问答平台：交付、评测与文档确认

版本：2026-09-16 R3。状态：文档修订待确认，但参数部分（D-03—D-07）已于同日冻结，仅 D-08 待确认；不是实现或验收报告。

## 1. 目标与范围

目标：完成可部署、可演示、可复现评测的通用知识管理与 AI 问答平台，用真实工程成果支撑简历和面试。原始需求 2.9.1—2.9.10 仍为范围依据；保留 PRD 的 10 模块、60 功能点与原编号。

使用者仍为普通提问者、知识管理员、系统管理员。知识维护、鉴权检索、问答、FAQ/缺口和运营属于同一平台的模块，首版采用分层单体。通用指知识内容领域可替换，不承诺任意行业、任意文档或任意问题都能准确回答。

非目标：电商客服渠道接入、订单物流查询、退款执行、产品 SKU 主数据、售后坐席工作台、通用智能体编排、多租户 SaaS。先前讨论的售后专用 R3 仅为未采纳建议，不构成需求变更。

财务人事用于验证数据隔离；客服退换货 FAQ 用于验证沉淀闭环。两者均为模拟场景，示例内容明确标注为测试资料，不构成现实政策。沿用 Vue/FastAPI/MySQL/Milvus 方向，无新增生产承诺。

## 2. 文档权威与兼容性

用户最新明确要求优先；DESIGN_REVISION 保留安全与一致性契约；PRD/FUNCTION-MAP 定义产品与函数。本文件补充定位、证据和文档确认门槛，不能覆盖原有安全规则。发现正文冲突应修正文档，而不是只靠优先级隐藏矛盾。

R3 是定位及交付修订，继承 R2 功能编号和安全规则，不代表重写 60 个功能点。本轮补充原页面所需接口和逻辑实体，详见API/DATA契约；没有业务代码变更。归档旧图、INTERVIEW 的历史段落、REUSE_NOTES 和历史 WORKLOG 均不得作为当前实现证据。

## 3. 分阶段交付与出口

1. D0 文档确认：核对范围、权限真值、状态机、接口与实体映射、图文一致性；处理第 7 节清单。当前停留此阶段，用户确认前不进入编码。
2. D1 最小贯通：修正权限实现与测试，完成最小登录/组织数据、上传解析、版本索引、非流式混合检索、授权生成和引用。以一份公开文档和一份受限文档实际演示全链路。临时种子数据不能代替最终组织管理界面。
3. D2 工程完整性：补齐组织与功能权限界面、批量/文件夹导入、切片维护、撤权、删除与过期任务、流式事件恢复和审计。验证异常链路而不只验证成功问答。
4. D3 知识运营：FAQ 候选、人工审核、缓存鉴权、日志聚类、缺口补档回放、运营指标；完成客服场景全流程。
5. D4 可复现交付：干净环境部署、实际后端集成、质量评测、故障与恢复演练、演示录像、已知限制、简历证据整理。

每阶段附版本、操作/命令、样本、预期、实际与失败记录。不得用参考项目结果替代本平台结果，不沿用历史工期；D0 收敛后按任务重新估算。

## 4. 评测数据与方法

### 4.1 数据规范

新增业务评测集应记录 case_id、场景、query、user_fixture_id、corpus_version、相关 unit_id/稳定片段定位、期望结果类型、必答要点、禁止披露内容、引用要求；多轮案例增加前置会话和身份变更步骤。密码、令牌、真实个人资料不进入公开样本。

建议首轮构建 60—100 条人工核验案例，具体数量是计划而非已完成。覆盖精确关键词、同义改写、多文档答案、多轮追问、无证据、部分/全部受限、四维权限、撤权、过期索引、FAQ 失效、解析失败。各类分别报告样本量。

调参集与保留测试集按文档主题及近似问题组划分，防止同义问题跨集合造成数据泄漏。保留集不用于阈值调优。切片策略变化时重新映射相关片段，不用旧 chunk_id 冒充有效标注。

data/golden 现有 query/expected/compliance 数据仅为历史起点，没有相关文档标注和身份权限上下文，不能直接证明本项目 Recall@K 或四维鉴权正确性；通用内容合规标签不等于知识访问授权。

### 4.2 指标定义

- 授权 Recall@K：前 K 项中命中的相关可读单元数 / 标注相关可读单元数；报告宏平均、K 和评测单元粒度。分母为零的案例单列，不填 100%。
- MRR@K：第一条相关可读结果排名的倒数，未命中为 0；纯拒答案例不纳入排序质量。
- 答案依据充分性：人工检查关键结论是否由有效授权证据支持；报告通过案例数/已评案例数。模型评分只能辅助，不作为唯一判据。
- 引用准确性：支持所关联结论的有效引用数/已评引用数；应有引用但缺失另计，不能通过不输出引用抬高准确性。
- 安全：逐案例检查 Prompt、重排输入、答案、引用、历史及 FAQ 出口；任何未授权正文或受限元数据披露均阻断交付。零次观测失败不等于数学上证明零风险。
- 性能：记录硬件、模型及配置、文档/切片规模、并发、冷暖缓存、样本量、错误率、首字/终态 P50/P95；FAQ 精确命中和语义命中分开。
- 用量：生成、embedding、rerank 分别记录；缺失为 unknown；成本估算附单价来源日期，不写成已支付账单。

建议比较关键词、向量、混合、混合+重排四种配置，所有配置使用同一数据版本和授权规则；记录效果与耗时，不预先断言重排一定提高效果。

### 4.3 必须保留的失败用例

创建者/超管默认无读权；直属与祖先部门区别；部分受限仍回答有权内容；全受限不猜测；FAQ 多来源任一不可读即不直出；权限撤销后重连复核；文档更新后旧切片不可用；服务故障不进入缺口；未知 Token 不记零。

## 5. 函数与接口准备要求

FUNCTION-MAP 现有签名是设计记法。开发前逐模块落定 DTO 必填/可空/长度、分页、错误码、幂等键、事务边界和调用依赖；不能将“按逻辑指定的仓储”视为已明确的可执行接口。

为 H08 检索、H10 Prompt、F-10.03 回放、F-10.04 发布验证补充评测用例映射。评测器放独立验证入口，不创建面向普通用户的任意模型输入查看接口。安全审计证据只对授权测试人员开放，公开演示使用脱敏夹具。

embedding 模型改变必须使用一致的查询/文档向量空间；不得把 local_bge 当作可直接查询旧 qwen 向量的热降级。确需切换时重建独立索引并验证切换/回滚。当前配置中的降级注释不构成已验证方案。

## 6. 简历与演示证据

- 设计：允许描述“设计了”，附规格和取舍；没有代码不能写“实现了”。
- 实现：附代码版本、测试与演示；部署在个人环境写“自部署”，不写企业上线。
- 评测：数字必须能回溯数据集、配置和结果；合成负载注明压测，不能写成真实用户量。
- 业务效果：模拟场景不能推导真实降本或客服效率提升；没有真实业务对照不写百分比收益。
- 复用：注明参考组件和本人工作边界；对外发布前确认实际使用依赖及素材许可。

交付证据至少包括部署说明、样例文档、账户角色说明（凭据单独安全提供）、正负向演示步骤、评测报告、测试与故障记录、恢复报告、当前架构图、限制清单。证据缺失时对应简历表述保持待验证。
